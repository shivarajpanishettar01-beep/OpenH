# OpenH rig: research, audit and fixes (report, 17 Oct 2026)

IIT Mandi's contribution to Open-H Embodiment V2: UR7e + Telemed probe (micrus) + wrist D415, ROS 2 Humble,
10 h of phantom data (vascular 6 h, central line 4 h), 20-30 s episodes, about 20 % failure / recovery.
Sample due **1 Dec 2026**, validated data **31 Jan 2027**.

## Verdict
- **Software: ready for the hardware bring-up.** Every finding of the 16 Oct audit is fixed, each with a
  regression test that fails on the old code. The live simulation run found 4 more problems, also fixed.
  - Result: 283 tests pass under ROS 2 Humble.
  - The synthetic export pipeline check passes end to end, with LeRobot 0.6.0 and v3.0.
  - A real Stage 0 episode flow passes in simulation through the real console and episode_manager.
- **Blockers:**
  - The real arm is untested: RTDE is not enabled yet, 27 rig.yaml values are null, and no calibration has been done.
  - One data-format decision is open: Open-H v2 now requires **absolute** end-effector poses for `action` and
    `observation.state`, while our export writes incremental poses (see §2).

## 1. What was done (16-17 Oct)

**Audit.** Five independent auditors read all 12 packages and the export chain. They reported 22 prioritised
findings (`docs/COLLECTION_READINESS_AUDIT.md`), and every critical claim was re-read at the cited line.

**Fixes.** 32 commits on top of 630f4b0. One finding is fixed per commit, each with a test:

| Area | Fixed |
|---|---|
| Safety | Console PROTECTIVE STOP was refused while another console action ran. A UR protective stop / not-RUNNING robot / refused command now faults (re-uploads the control script on ack). Perturbations are refused in free air. The phantom box is never briefly absent on reload. The in-contact hold is set before it runs. The test suite ran on the rig's ROS domain (it could have commanded a live rig). |
| Labels in the data | FAULT, deadman and in-contact-hold samples were labelled expert. `/robot/cmd_executed` had gaps during FAULT. An onset key overwrote a disturbance onset. Automated labels overrode expert labels in the export (resolver: expert > model-assisted > trainee > automated; rejected labels dropped). |
| Recording / QC | Depth-rate QC failed **every** camera episode under ~35 s (measured 38.4 Hz for 30 Hz). Streams that stop mid-episode now fail. Free disk is checked before Start instead of failing recorded episodes. A failed micrus stop no longer loses the episode. Unexpected errors discard one episode instead of ending collection. QC runs after the retract; discards skip QC. QC that never ran is run on restart. |
| Session flow | Each new session needed launch, exit, check and relaunch; one launch now, and the pre-session check is gated at Start. The console never passed the planned hours, so its check could never pass. A phantom registration made mid-session never reached robot_state / `/tf_static` (verified live on URSim). Waypoints followed session.yaml instead of the session's phantom. |
| Stage 2 plans | Plan progress restarted at row 0 every session; it now spans sessions. Redo rows get a second pass. The next row (failure mode, staging method) is shown before it starts. The generator tied each failure mode to one target (confounded); it is now stratified, with per-phantom exclusions. The 1→2 gate could block forever. |
| Export / labels | Per-annotator files, blind mode, and "accepted" counts toward agreement. Failure class comes from the plan FM id. Index/offset cross-checks. Per-session calibrations with exact frame names. One `exportable(ep)` rule for all hour counts. Pre-roll / paused / last-action steps are flagged. The card is also written to `meta/README.md` with a Synchronization section (Open-H validator). |
| Robustness | robot_state never publishes a sample with a missing RTDE field. bag_check verifies that pose, joints and force are actually read (F/T live). |

**Bugs found in the live runs (simulation, 17 Oct):**
- **episode_manager crashed at Start (pre-existing, intermittent).** Destroying the recorder's readiness subscriptions while the 4-thread executor served them raised InvalidHandle. Reproduced in isolation; fixed by giving them their own executor.
- **Orphaned `ros2 service call` processes** were left after a SIGKILLed shutdown. The call now carries its own time limit.
- **Console outcome race.** Stop right after Success asked for the outcome again.
- **The disk gate works live.** This PC has 29 GB free (floor 50 GB), and Start is refused with the reason.

## 2. Research: what Open-H V2 expects (sources opened 16 Oct 2026)

Source for this section: the open-h/open-h-embodiment repository (README, AGENTS.md, the V2 RFP, `validate_formatting.py`) and arXiv 2604.21017.
- **Schedule:** data sample 1 Dec 2026; cleanup Jan 2027; training Feb; release Mar 2027.
- **Hours:** the phantom minimum is **8 h** at weight ×1. Hours are counted as `total_frames / fps / 3600`, so pre-roll and paused steps count. Our steps are now flagged.
- **Format:** LeRobot **0.6.0**, dataset format **v3.0**. Required items:
  - `meta/README.md`, written from their dataset template;
  - task-and-target text per episode;
  - calibration files;
  - a robot kinematic description (URDF).
- **Kinematics (changed from v1):**
  - `action` and `observation.state` = **absolute Cartesian EE pose** `[x, y, z, qx, qy, qz, qw, gripper]`.
  - `action` is the commanded setpoint, not a velocity.
  - Joints go in `observation.meta.joint_positions`.
  - Force goes in `observation.meta.force_torque`, with sensor, units and frame stated.
  - Quaternions are resampled with Slerp.
- **Validator** (`scripts/validation/validate_formatting.py`, requires lerobot == 0.6.0):
  - ERROR without `meta/README.md` (fixed), `action` / `observation.state`, `stats` or `tasks`.
  - WARNING below 20 Hz, below 480 px in either image dimension, or without a train/val/test split.
- **Video:** lossy MP4 is normal (v1 ultrasound used AV1). No lossless requirement was found. Keep the micrus HDF5 as the lossless master.
- **Recovery data:** "DAgger-style recovery demos are as valuable as successful demos". Per-episode success / failure / recovery flags are encouraged.
- **Comparable data:**
  - US-VLA and ForceU-VLA (same UR7e): 320 and 450 teleop trajectories at 15 Hz, about 1.5-1.9 h, with no failure or recovery data.
  - No UR7e ultrasound dataset is in Open-H v1, and no v1 ultrasound dataset has recovery examples. Ten hours with labelled failure / recovery and force would be distinctive.
- **Collection practice:**
  - Diversity beats repetition (data-scaling-laws study).
  - Draw a random task per episode and change the setup about every 20 minutes (DROID).
  - Script the transit and give the human the hard segment: over 3× more demonstrations in the same time (HITL-TAMP).
  - Collect recovery as interventions (RaC: about 10× less collection time).
- **UR specifics:**
  - The frame of `actual_TCP_force` is not stated in the RTDE guide. Test it on the arm.
  - `safety_mode` is deprecated in favour of `safety_status_bits` on PolyScope 5.4+.
  - **The UR Freedrive input does not work while a program runs.** Our freedrive collection already requires robot_control to be stopped, so this is consistent; confirm it on the arm.

The full brief with 41 references is in the session transcript. Its key claims are cited above from the
primary sources the research agent opened.

## 3. Decisions needed from you
1. **Action / state format (blocker for 1 Dec).** Proposal item 4 says incremental TCP actions; Open-H v2 says absolute EE pose. Proposed:
   - `action` = next commanded / measured absolute pose `[x y z qx qy qz qw]`;
   - `observation.state` = measured pose;
   - joints → `observation.meta.joint_positions`;
   - keep the delta action and the executed twist as `observation.meta.*`.
   Ask Open-H (contact named in their repo) two things: the gripper slot for a probe, and the action for **kinesthetic** episodes, where no setpoint exists.
2. **Failure class mapping** (`annotation.py FM_FAILURE_CLASS`, open decision 20). The export agent proposed this table; confirm it against your failure-mode protocol.
3. **Stage 2 mix.** The default is 15 % failure + 30 % recovery per plan; Stage 2 is the only source of failure and recovery data. The dataset-wide target is 20 %. Set `--fail-frac` / `--recovery-frac` when generating plans.
4. **Run Open-H's validator** on the first sample export (external code; run it in `openh-export`).
